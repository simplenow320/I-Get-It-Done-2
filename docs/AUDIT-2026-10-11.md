## Team: what was broken

1. **Teammates never saw tasks handed to them.** The "Assigned to Me" query compared `completed_at = NULL`, which is never true in SQL. The list was always empty. This was the core of the feature.
2. **Teammate hand-offs vanished from Task Detail.** The screen only showed a hand-off when it went to an offline contact. A hand-off to a linked teammate looked like no hand-off at all, with no status, no notes and no way to unassign.
3. **Hand-off data was dropped on every reload.** The app threw away `delegatedToUserId` when loading tasks. Status changes, notes, contact hand-offs and unassign were saved on the phone only and lost on the next refresh.
4. **Anyone could read or change anyone's team.** 15 Team endpoints had no login check and trusted a user id from the request body. Proven live: an anonymous request renamed a user, read a team roster, spoofed a teammate's status update and injected notes and subtasks on another person's task.
5. **Invites typed with capital letters never arrived.** Emails were not normalized.
6. **A teammate with a handed-off task could not delete their account.** The delete failed with a database error, which is an App Store 5.1.1(v) problem. It also wiped half the data before failing, because nothing ran in one transaction.
7. **Regenerated invite codes** used confusable characters (0, O, 1, I) in 13 of 20 samples, and could come out shorter than the 8 characters the Join screen requires.
8. **The Team code field in Mode Settings did nothing.** It saved the code on the phone and never joined the team.
9. **No notifications.** The hand-off notification existed but was never called. Owners were never told when a teammate updated status.
10. **Screens went stale.** The Team tab only loaded once per app launch, so new invites, links and assignments never showed up.
11. **Removing a teammate left them with your tasks**, despite the dialog promising otherwise.
12. **On web, every confirm dialog silently did nothing** (remove member, cancel invite, delete task, unassign), because `Alert.alert` is a no-op in the browser.

## Team: what I changed

- Every Team endpoint now requires login and uses the signed-in user, never a body id. Old App Store builds still work: they send matching ids, which are accepted.
- Fixed the Assigned to Me query. Teammates see their tasks, the owner's name and the full note thread.
- Hand-offs only go to linked teammates. The teammate gets a push ("New task assigned"), and the owner gets one when the teammate changes status. Tapping either opens the right screen.
- Task Detail shows teammate hand-offs with a "Linked" badge, live status, notes and Unassign.
- Every hand-off action now saves to the server. A failed hand-off rolls back and tells you, instead of showing a hand-off your teammate never got.
- Team Hub and Assigned to Me refresh on open, every 30 seconds while open, on pull-down and when the app returns to the foreground. Linked teammates show their open task count.
- Removing a teammate is mutual and releases open hand-offs both ways. Account deletion releases hand-offs first and runs as one transaction.
- Invite codes use a secure random generator, a safe alphabet and a uniqueness check. Resend refreshes the 7-day expiry. Join is rate-limited against guessing.
- Mode Settings actually joins the team with the code you enter.
- Web-safe dialogs everywhere (`client/lib/alerts.ts`), and real server error messages instead of "Failed".

## Voice recording: what was broken

1. **No recording on web.** Tapping the mic showed an alert that is invisible in browsers, so nothing happened at all.
2. **The daily quota could be skipped** by sending a duration of 0.
3. **A recording that ran past the remaining quota was thrown away** after the user finished speaking.
4. **No length limit or timer.** A forgotten recording ran until the 25 MB upload limit.
5. **A server-side Deepgram key problem told users "Session expired, please log in again."**
6. **Every transcript was written to the server logs**, which is a privacy problem.
7. **Audio type was hard-coded** to the phone format, so browser audio was mislabeled.
8. **Quick Dump dropped your words** when AI extraction failed or found no tasks.
9. **Leaving the screen mid-recording** left the mic and the iOS audio session open.
10. **`expo-file-system` was never declared as a dependency.** The recorder only worked because the lockfile happened to hoist it. Any dependency change would break the build.

## Voice recording: what I changed

- Browser recording through `expo-audio` (WebM on Chrome/Firefox/Edge, MP4 on Safari). Proven in Chromium with a real MediaRecorder upload.
- A live timer, auto-stop at 5 minutes or when today's quota runs out, and a "too short" guard.
- Quota billing uses the longer of the client's and Deepgram's duration. A recording started with time left is always transcribed.
- Deepgram errors return 502/503/504 with clear messages, never 401. 60-second timeout. Transcripts are no longer logged, only lengths and timings.
- The real audio type is passed to Deepgram.
- Quick Dump puts what you said into the text box when no task is found or AI is down, so nothing is lost.
- Clean stop on unmount and when the phone app goes to the background. iOS "inactive" moments (Notification Center, call banner) do not cut a recording.
- `expo-file-system@~19.0.19` declared in `package.json` and the lockfile (same version already installed, one line each).
- Fixed the compact recorder layout that pushed the "+" button off screen.

## Other features: fixed

- **Crash:** Focus Mode and Weekly Reset called hooks after an early return. Upgrading, a trial ending or a slow subscription check while the tab was open crashed to the error screen.
- **Offline tasks were wiped.** Tasks created offline are now queued on the device and re-sent, never erased by the next sync.
- **Notes could not be cleared**, **completed tasks could be completed again** for double points, **toggling a subtask off and on paid points again**, **lane timing settings were ignored**, and **overdue moves sometimes never saved** (stale state). All fixed.
- **Focus timer stopped when the phone locked.** It now runs off a wall-clock end time and catches up on return.
- **Points and streaks were shared by everyone on a device** and rolled over at UTC midnight (5pm Pacific). Now per account, local midnight, and a broken streak shows as broken. Existing progress is kept.
- **Server stats:** completions count exactly once even when the app, a notification "Done" and Claude complete the same task at once. Streak days use the user's local date.
- **Notifications:** due-soon fired up to 4 times a night per task (now once, batched, outside quiet hours). Escalating nudges only worked if the app had been opened (now detected server-side) and could fire every 10 minutes for users with many overdue tasks (now paced per user). Streak saver warned about streaks that had already died (fixed). One dead phone token switched off browser notifications too (fixed). Opening the web app re-enabled notifications a user had turned off (fixed). Daily reminders silently stopped after sign-out and back in (now restored at sign-in).
- **Privacy:** signing out now detaches the phone or browser from the account, so the next person on that device never gets your task reminders. RevenueCat entitlements are cleared on sign-out.
- **Password change:** typing the wrong current password logged you out (it returned 401). Change and reset now use the same rules as sign-up. Reset codes lock after 5 wrong guesses and are rate-limited. Reset codes are no longer logged.
- **Paywall:** prices outside the US showed "$£49.99" and "SAVE NaN%". Upgrade buttons could strand you on Subscription with Profile unreachable. Subscribe and Restore gave no feedback on web.
- **RevenueCat webhook:** a cancellation removed Pro immediately even though the user had paid through the period. Transfers were ignored. Without the secret set, anyone could grant themselves Pro.
- **Claude connector (OAuth):** added a per-IP sign-in limit and a registration limit, and the consent page now shows where access is being sent.
- **Server hygiene:** task updates accept only editable fields (they used to accept any column, including the owner id). The push-token endpoint no longer returns password hashes. The error handler no longer kills sockets. Migration `0002` backfills tables and columns that only ever existed through `drizzle-kit push`, and adds indexes for Team lookups.

## Not changed, and why

| Item | Why left | Suggested next step |
|---|---|---|
| Voice and AI endpoints don't check Pro on the server | Turning this on while the RevenueCat webhook may not be configured would block paying users from recording. | Confirm webhook delivery, then add a server-side Pro check. |
| Changing a password doesn't sign out other sessions | Needs a token-version column and a check on every request. | Add `password_changed_at` and compare to the token's issue time. |
| Gamification still has two point systems (app vs server) | Merging them changes product rules. | Pick the server as the source of truth in a follow-up. |
| Edits made offline to existing tasks can be lost | New tasks are now protected. A full offline edit queue is a bigger feature. | Queue PUTs the same way creates are now queued. |
| Notification scheduler runs inside the web server | With autoscale, instances can sleep through reminder windows. | Use a Reserved VM deployment or a scheduled job. |
| "Remember me" checkbox does nothing | Cosmetic. | Remove it or honor it. |
| Onboarding and team mode are stored per device | Needs a server column. | Store on the user record. |
| Repo-wide Prettier formatting | The code freeze forbids reformatting. | Run `npm run format` in its own commit when ready. |

```
npm run test:mcp
node tests/oauth-flow.test.mjs
```
